Implementation Notes — Phase 4

authkit-laravel-v1 · Events Pipeline & Webhooks · 2026-08-09

Projection listeners — Phase 1–3 interface names reconciled (spec Open Item 1 resolved)

Context
The spec's Prerequisites table assumed Authkit\Authkit\Models\OrganizationDomain/OrganizationMembership, config key authkit.organizations.model (plural), and user resolution via auth.providers.users.model, flagging all three as the phase's biggest accuracy risk.
Decision
Reconciled against landed code: models are WorkosOrganizationDomain (columns workos_id/organization_id/domain/state/verification_prefix/verification_token) and WorkosMembership (workos_id/organization_id/user_id/role/status); the org config key is singular authkit.organization.model and may be null (org listeners no-op then, mirroring UpsertOrganizationAndMembershipFromLogin); the user model resolves through auth.providers.workos.model falling back to auth.providers.users.model (the AuthKitController::userModel() chain), so the projection always refreshes the row the guard retrieves.
Alternative
Implementing the spec's literal names — every domain/membership listener would target nonexistent classes and the user projection could refresh a different table than the guard reads.

UpsertUserProjection — column mapping and collision semantics for the landed users table

Context
The spec's listener body writes ['external_id' => ...] but flags it "illustrative — verify column names before implementing". The landed users table has no external_id column: it is the skeleton (name NOT NULL, email unique, password nullable) plus Phase 2's nullable-unique workos_id.
Decision
Upsert keyed on workos_id writes email + display name (name ?? trim(first last) — the HasWorkosUser derivation). Link-by-email only when the payload says email_verified, mirroring the trait's account-takeover gate. An UNVERIFIED collision with an existing local email logs a warning and skips instead of throwing: a throwing poller listener would replay the same batch forever (poison event), unlike the login flow where the same collision throws to a human. A brand-new row floors name at '' to satisfy NOT NULL name columns for name-less WorkOS users (the trait does the same at creation); an existing row's name is never clobbered by a name-less payload.
Alternative
Blind updateOrCreate on workos_id — first unverified-email collision would crash the batch with a unique-constraint violation and stall the cursor permanently.

Webhook macro — CSRF exclusion covers both supported Laravel majors, via class_exists-filtered strings

Context
The spec excludes only PreventRequestForgery, correct for the vendored Laravel 13.24 where it is what the web group applies. But composer supports ^12.0||^13.0 and CI runs PHPStan + the suite on Laravel 12, where PreventRequestForgery does not exist and the web group applies ValidateCsrfToken — excluding only the L13 class would 419 every webhook POST on L12, and referencing it as a ::class import would fail PHPStan on the L12 lanes.
Decision
The macro excludes array_filter(['...PreventRequestForgery', '...ValidateCsrfToken'], 'class_exists') as string literals: on L13 the applied parent matches exactly (the deprecated-child entry is harmless), on L12 ValidateCsrfToken matches exactly. A dedicated test asserts both are in the route's excludedMiddleware() — postJson cases alone cannot prove it because PreventRequestForgery bypasses itself under runningUnitTests(), exactly as the spec warned.
Alternative
Excluding only the spec's single class (breaks the entire webhook surface on Laravel 12), or dropping L12 support (out of this phase's authority).

Daemon-loop regression test — sentinel listener exception instead of the spec's OS signal

Context
The spec's component-5 experiment stops the no---once daemon with a signal after two empty batches to prove lock renewal (refresh vs get). But Command::trap() is a framework-enforced no-op in tests: ArtisanServiceProvider's Signals availability resolver requires ! runningUnitTests(), so a real SIGINT kills the whole pest process (observed: exit 130).
Decision
The daemon is stopped by a listener that throws a sentinel RuntimeException on the third batch. Reaching batch 3 proves two full loop iterations — two successful in-loop refresh() calls on the held lock — completed without the lock-loss FAILURE branch, which is the regression the experiment targets; a get() regression fails this test immediately. Real signal handling remains covered by the spec's manual-testing checklist (SIGTERM on a Unix dev machine).
Alternative
Force-overriding Signals::resolveAvailabilityUsing() mid-test to allow posix_kill on the pest process — mutates internal framework statics and leaves the test runner's signal disposition altered on failure paths.

WorkCommand — processor is method-injected into handle(), not constructor-injected

Context
The spec's snippet constructor-injects EventBatchProcessor. Artisan instantiates registered commands once per console process, so a constructor-held processor pins whichever client manager existed at console boot.
Decision
handle(EventBatchProcessor $processor) resolves at execution time, picking up the current container state — required for the MockHandler harness (fakeWorkosResponses() forgets the manager instance after commands are already instantiated) and consistent with the provider's bind-not-singleton policy for SDK-derived services.
Alternative
Constructor injection per the spec's literal snippet — every worker test would silently hit the real HandlerStack instead of the queued MockHandler responses.

Events suites — MockHandler-primary with one emulate smoke test (sanctioned downgrade, evidence recorded)

Context
The spec's Feedback Strategy runs the whole events suite against emulate. Live probing of @workos/emulate@0.6.0 found: GET /events parses via EventSchema::fromArray and seeded users/orgs/domains emit *.created events (wire fidelity works), but an unresolvable after cursor returns 200 with the full list — never the 400/404 the stale-cursor fallback catches — and range_start format is not validated (date-only accepted), so neither spec-critical path is exercisable against emulate.
Decision
Per the contract's truth bar ("MockHandler fakes only where emulate lacks coverage") and the Phase 2/3/5/7/9 one-smoke-test precedent: EventsWorkerTest keeps one emulate smoke test (seeded events walked over the real wire, cursor advance + second-poll-empty), everything else — cursor-commit timing, stale-cursor fallback, exact range_start format regex, crash/resume determinism — is MockHandler-backed and therefore also runs on the Windows CI lane, where the named success-criterion suites must pass and emulate is unavailable.
Alternative
Seeding 10-event batches into emulate at runtime for the resume suite — portable only to POSIX CI, and still unable to produce the 400-stale-cursor or format-rejection behaviors the spec's experiments demand.

config/authkit.php — events subtree placeholders replaced, not appended around

Context
Phase 1 shipped an events subtree with enabled and cursor_cache_store placeholder keys no code reads (grep-verified); the spec's Data Model defines the subtree as poll_interval/batch_limit/backfill_minutes/lock_ttl.
Decision
This phase owns the subtree (Phase 9 precedent with the vault placeholder): dead keys removed, spec keys added, existing poll_interval kept. The cursor is DB-backed by contract decision, so cursor_cache_store could never have a consumer; an unread enabled flag would imply a gate the worker doesn't implement.
Alternative
Keeping the dead keys alongside the real ones — config that promises behavior nothing implements.

php artisan dev integration — vendored 13.24 deprioritizes vendor registrations instead of refusing them; docs-only stance kept (spec Open Item 2)

Context
The spec's Component 10 (researched against 13.16) states DevCommands "explicitly refuses" vendor-sourced registration, and ships two documented recipes instead of package code, instructing re-verification at implementation time and to "ship both documented recipes regardless of which one turns out current".
Decision
Vendored 13.24 reality: resolvePriority() assigns vendor-sourced calls PRIORITY_VENDOR (1) vs userland (2) — registrations from vendor/ DO register and appear in `dev`, but any same-name userland registration overrides them. Both recipes shipped in docs/quickstart.md plus the inert commented example in WorkbenchServiceProvider::boot(), per the Open Item's explicit instruction. Package self-registration would be new cross-version runtime surface (DevCommands does not exist on Laravel 12) beyond this phase's scope — left for a later phase to promote deliberately.
Alternative
Self-registering authkit:work from AuthkitServiceProvider behind class_exists(DevCommands::class) — now technically possible, but unspecced behavior the contract's decision log never re-approved after the 13.16 finding.

workbench/routes/web.php — macro call guarded with Route::hasMacro (codebase surprise: Larastan boots workbench routes)

Context
The spec's workbench example is a bare Route::workosWebhooks('workos/webhooks');. Larastan's application bootstrap loads workbench routes without the package provider's boot() having registered the macro — PHPStan then died with exit 1 and literally zero output (a uniquely silent failure worth recording: bisected by stashing the routes file).
Decision
Wrapped the call in if (Route::hasMacro('workosWebhooks')). The Phase 13 grep target (Route::workosWebhooks(, zero SDK references) is intact, composer serve still registers the route, and every analysis/bootstrap path that loads routes before package boot degrades gracefully.
Alternative
Moving the example into a workbench provider boot callback — hides the one-line-in-routes-file usage the docs promise apps.

WorkCommand — refresh() lives on the abstract Illuminate\Cache\Lock, not the Lock contract; instanceof guard added

Context
The spec's lock-renewal rationale cites ArrayLock::refresh(). Cache::lock() is typed to the Illuminate\Contracts\Cache\Lock CONTRACT, which has no refresh() — the method exists on the abstract Illuminate\Cache\Lock every framework driver extends (and the base implementation throws for drivers that don't override it, e.g. CacheLock-based stores).
Decision
The command narrows with instanceof Illuminate\Cache\Lock and exits FAILURE with a store-naming error when a custom store returns a bare contract implementation — renewal-incapable locks must fail loudly before the loop, not silently race a second poller after TTL lapse.
Alternative
Calling refresh() unchecked — passes at runtime for every framework driver but is a PHPStan level 7 error and an undefined-method fatal for contract-only custom locks.
