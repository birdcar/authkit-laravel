Implementation Notes — Phase 12

authkit-laravel-v1 · Depth Extensions (Full Tier) · 2026-08-10

InvalidateFgaCache — listeners registered unconditionally, not gated on authkit.fga.cache.enabled

Context
The spec's provider diff wraps Event::listen(...) in if (config('authkit.fga.cache.enabled')), reasoning "no reason to attach listeners for a cache that's disabled."
Decision
Register both listeners unconditionally in boot(). FgaChecker::forgetCache() is already a config-guarded no-op, so behavior is identical when disabled (verified by a test asserting no generation key is written on a membership event while off). Gating at boot would pin the flag's boot-time value: any runtime config()->set (every Pest test, tinker sessions) would silently detach invalidation from an enabled cache — exactly the stale-decision failure the opt-in design exists to prevent — and would make the events-driven invalidation matrix untestable in the landed Testbench harness, where the flag defaults off when providers boot.
Alternative
Spec-literal conditional registration plus per-test application rebuilds (Testbench defineEnvironment machinery) to flip the flag before boot — rejected as heavier for zero behavioral gain and a real production footgun for anyone toggling config after boot.

JwtTemplateManager::update() — catches NotFoundException on the before-read

Context
The spec's update() unconditionally calls $this->get() to capture the before-content for JwtTemplateUpdated. WorkOS (and emulate, whose route comment cites the spec) 404s GET /user_management/jwt_template until an environment has ever set a template — so the spec-literal body would make the first-ever template write throw NotFoundException, and setting up a template initially is the primary use of this API.
Decision
Catch NotFoundException around the before-read and treat the previous content as ''; the event's $previousContent docblock documents the empty-string meaning. Covered by a MockHandler test (404 then 200) asserting the event carries previousContent === ''.
Alternative
Letting the exception surface (spec-literal) — rejected because it breaks the component's own purpose on fresh environments and the spec's failure-mode table never lists it as intended behavior.

HasWorkosResource — parent guard uses instanceof WorkosResource; parent target is the package ResourceTarget, not the SDK class

Context
The spec snippet guards with in_array(self::class, class_uses_recursive($parent)) — but inside a trait, self::class resolves to the using class, so the check would ask whether the parent uses e.g. Project as a trait and always fail. The snippet also has the trait build \WorkOS\Service\ParentResourceByExternalId directly, and assumed a syncAsWorkosResource() method that Phase 5 never shipped (sync is created/deleted boot hooks calling Authkit::resources()).
Decision
Guard with $parent instanceof Contracts\WorkosResource — the landed interface every HasWorkosResource model must implement (@phpstan-require-implements) — and have workosParentResourceTarget() return the package's ?ResourceTarget, converted to the SDK pair inside ResourceManager::create() via the new toParentTarget(). This honors the landed boundary doctrine (ResourceTarget exists precisely so consumers and package seams never name SDK service classes) and wires the parent through the real sync path: the created hook gains parentResource: and both hooks gain the post-sync forgetCache().
Alternative
Correcting the trait-name check to in_array(HasWorkosResource::class, class_uses_recursive($parent)) — behaviorally equivalent but weaker than the contract check the codebase already types against; passing SDK parent objects through the trait — rejected per the boundary doctrine.

FgaChecker — cache branch reads once with type narrowing instead of the spec's has()+get() pair

Context
The spec snippet does if ($store->has($key)) { return (bool) $store->get($key); } — two store round-trips with a TOCTOU gap (an entry evicted between the calls silently becomes (bool) null === false, turning a cache race into a deny).
Decision
Single $store->get($key) narrowed with is_bool() — only values this cache wrote are servable; a miss, an eviction race, or a corrupted entry all fall through to the live check. The generation-key read inside cacheKey() sits inside the same try/catch so a store fault at either read fails open identically.
Alternative
Spec-literal has()+get() — rejected for the race and the double round-trip on network-backed stores.

InvalidateFgaCache — hand-authored instead of the testbench make:listener scaffold-then-relocate step

Context
Spec step 1 for Component 7 scaffolds the listener with vendor/bin/testbench make:listener InvalidateFgaCache --invokable, then moves the file, renames its namespace, and replaces the invokable stub with two named handlers — i.e. zero generated content survives.
Decision
Hand-author src/Authorization/Listeners/InvalidateFgaCache.php directly, matching the landed listener shape (every one of the ten Phase 4/6 listeners in src/Listeners/ is hand-authored; none came from the generator, which also writes into the shared Testbench skeleton other parallel suites read).
Alternative
Running the generator as ritual — rejected as pure churn with a workbench-pollution risk and no retained output.

Workbench demo routes — organization id from the query string; workbench.demo_organization_id does not exist

Context
The spec's routes read config('workbench.demo_organization_id'), flagged in Open Item 5 as "assumed to exist by Phase 3; confirm the real key." No such key (nor any workbench config file) landed in any phase.
Decision
The three routes take organization_id from the request (query/body), falling back to the spec's config key so it starts working if a later phase introduces it. The groups route 422s with a usage hint when neither is present (its SDK call requires a non-null org id); the invitations routes pass null through, which the list/send APIs accept.
Alternative
Introducing a workbench/config/workbench.php just for a demo id — rejected as out of phase scope (no other phase created workbench config; request input is the established playground pattern, cf. the API-key whoami route).

GroupManager — roleAssignment() single-fetch added; spec snippet omitted a method its own wrapped-methods list names

Context
Component 4's "SDK methods wrapped" list includes Authorization::getGroupRoleAssignment, but the class design snippet has no corresponding method.
Decision
Ship roleAssignment(string $groupId, string $roleAssignmentId): GroupRoleAssignment so the wrapped-surface table is honored; read-only, no cache interaction.
Alternative
Following the snippet only — rejected; the enumerated SDK surface is the scope statement, the snippet its illustration.

CORS origins — emulate 0.6.0 partially covers the area; suite stays MockHandler (Open Item 2 resolved)

Context
Open Item 2 asked to confirm emulate's CORS coverage. Probing the 0.6.0 dist routes: POST /user_management/cors_origins exists, but there is no list route — half the component's surface.
Decision
Keep CorsOriginsTest on MockHandler as the spec defaulted, which also lets it assert exact request shapes. The suite additionally pins the no-delete() scope boundary (Deviations 1 / Failure Mode 8) with a method_exists assertion.
Alternative
Splitting create onto emulate and list onto MockHandler — rejected; two transports for a two-method passthrough is complexity without added fidelity.
