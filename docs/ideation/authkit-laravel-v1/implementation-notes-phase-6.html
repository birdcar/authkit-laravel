Implementation Notes — Phase 6

authkit-laravel-v1 · Audit Logs & Admin Portal · 2026-08-10

Domain-verification listener — ownership transferred from Phase 4's generic upsert (spec Open Items 2/3, cross-phase seam)

Context
Spec §4.8 designs a dedicated verification listener (state stamping, token clearing, warn-and-no-op on unknown rows), but landed Phase 4 already routed OrganizationDomainVerified/OrganizationDomainVerificationFailed into UpsertOrganizationDomainProjection with contradictory, explicitly-tested semantics: tokens kept on verify, no state change on failure (the payload carries no top-level state), and rows created for unknown ids. Running both listeners would make §4.8's "warn + no row created" semantics unreachable and its token clearing fight the upsert.
Decision
The verification pair now belongs exclusively to the new UpdateOrganizationDomainVerificationState; UpsertOrganizationDomainProjection narrowed to Created|Updated; the two Phase 4 test expectations updated to the spec'd semantics. This matches spec §8 failure mode 8's own wording ("reconciled later by Phase 4's created/updated listeners"), which is only coherent under this split. Payload access uses the landed flat-array convention ($event->resourceId()), not the spec's nested organizationDomain object.
Alternative
Registering §4.8's listener alongside the Phase 4 upsert — rejected because the upsert's updateOrCreate would create rows before the new listener ran, breaking the unknown-row no-op, and two Phase 4 tests would fail as written either way.

AuditActorResolver — org id read from guard claims; Authkit::currentOrganizationId() never landed (spec Open Item 1)

Context
Spec §4.2 calls Authkit::currentOrganizationId(): ?string. Phase 3 landed Authkit::currentOrganization(): ?Model (local projection row, null when no org model is configured) and keeps the claims read private inside CurrentOrganizationResolver.
Decision
Per the Open Item's sanctioned adjustment, AuditActorResolver reads the org_id claim directly off Auth::guard('workos') via the landed HasAccessTokenClaims contract — audit events need the raw WorkOS org id whether or not the app configured a local org model, so routing through the projection-backed accessor would wrongly throw for claim-carrying sessions in model-less apps.
Alternative
Adding currentOrganizationId() to the Authkit manager + a public claims accessor on CurrentOrganizationResolver — a nicer public API, but it modifies a Phase 3 file outside this spec's File Changes table for no behavior the resolver-side read doesn't already provide.

AuditLogManager — bound, not the spec snippet's singleton

Context
Spec §6 registers AuditLogManager as a singleton. The landed provider deliberately bind()s every service that holds the WorkOS client manager (UserManagement/SessionManager/VaultCrypto/VaultManager precedent): the MockHandler test harness forgets the manager instance mid-test, and a singleton would pin the pre-swap client.
Decision
bind(AuditLogManager::class), with the provider comment naming the deviation. AuditActorResolver stays a singleton as spec'd (stateless, holds no client).
Alternative
Singleton per the spec snippet — breaks every MockHandler-backed test that fakes responses after first resolution (the exact failure Phase 9 recorded).

Test-path selection — emulate coverage empirically narrower than the spec's §7 table assumed

Context
Spec §7 routes createEvent/schema/retention through emulate. Probing @workos/emulate 0.6.0's dist source: POST /audit_logs/events reads a top-level action while SDK v9.1 nests the payload under event (always 422); action/schema responses lack the schema key AuditLogAction::fromArray requires (SDK parse fatal); listActionSchemas and PUT-retention routes don't exist (404). Conversely the spec's stated emulate export gap is outdated — the routes exist but auto-transition to ready, which still can't exercise the poll state machine.
Decision
MockHandler-primary for create-event/schema/retention/export suites with one emulate wire-fidelity smoke (empty listActions + GET retention, both parseable); AdminPortalTest stays emulate-backed as spec'd (portal mint fully works). Same sanctioned downgrade pattern Phase 5 recorded for legacy authorization shapes.
Alternative
Following §7's table literally — every emulate-backed audit case except the smoke would fail on wire-shape drift, not on package behavior.

HasAuditLogs — registerModelEvent('restored', …) instead of static::restored()

Context
The spec's trait boot calls static::restored(...), but that registrar only exists on models using SoftDeletes — on a plain model it falls through __callStatic into the query builder and fatals during boot.
Decision
Register via the protected static::registerModelEvent('restored', …) (available on every Model): the listener is inert on non-SoftDeletes models because the event never fires, and the trait boots cleanly everywhere. Archive/delete discrimination uses class_uses_recursive rather than method_exists, which PHPStan level 7 flags as always-true in the analyzed workbench context.
Alternative
Guarding static::restored() with method_exists — same runtime behavior but an undefined-static-method error at PHPStan level 7 for non-SoftDeletes trait consumers.
