# WorkOS SDK v5 Migration Contract

**Confidence Score**: 95/100

## Problem Statement

The authkit-laravel package currently depends on `workos/workos-php ^4.29`, which uses a static configuration model and lacks service classes for many WorkOS features. This forced us to build six manual HTTP implementations (FGA, Vault, Radar, Pipes, Domains, Events API, API Key validation) that bypass the SDK entirely — using raw Guzzle, Laravel `Http::` facade, and even the SDK's internal `Client::request()` method.

The WorkOS PHP SDK v5 (released 2026-04-13) is a complete rewrite autogenerated from their OpenAPI spec. It replaces the static configuration model with an instantiated client, adds native service classes for every feature we manually implemented, introduces typed resources with `DateTimeImmutable` timestamps, and renames virtually every method. This is both a breaking change we must absorb and a massive opportunity to simplify.

If we don't migrate, we stay pinned to a dead-end SDK version, our manual HTTP implementations diverge further from the official API surface, and we miss out on v5's auto-retry, typed exceptions, and auto-pagination features.

## Goals

1. **Upgrade to `workos/workos-php ^5.0`** with all existing features working and all tests passing (PHPStan level 8, Pest, Pint)
2. **Replace all 6+ manual HTTP implementations** with native v5 SDK service calls — zero raw Guzzle or `Http::` facade calls to WorkOS endpoints
3. **Wrap every v5 SDK service** through the `WorkOS` facade so Laravel developers have a single, consistent API surface for the entire WorkOS platform
4. **Maintain the `WorkOSSession` value object** as the typed Laravel-native session representation, adapting it to v5's plain-array session responses
5. **Stay pre-1.0** — this is a breaking `0.x+1` release; no backwards-compatibility shims

## Scope Boundaries

### In Scope

- Update `composer.json` SDK dependency to `^5.0`, resolve any secondary dependency changes (Halite 5.1, PHP 8.2+ already met)
- Rewrite `WorkOSServiceProvider` to instantiate the v5 `WorkOS` client and register it as a singleton
- Overhaul `WorkOS.php` service class: replace `SERVICE_MAP` + `__call()` magic with explicit v5 client delegation, update all service accessors
- Migrate `SessionManager` from v4 `CookieSession`/`loadSealedSession()` to v5 `$workos->sessionManager()`
- Adapt `WorkOSSession` value object for v5 plain-array session responses
- Update all controller/command method calls for v5 renames (e.g., `sendInvitation` -> `createInvitations`)
- Migrate webhook verification from return-value to exception-based pattern
- Migrate pagination from `PaginatedResource` destructuring to `PaginatedResponse->data` / `autoPagingIterator()`
- Replace `FGAService` (`Client::request()` internals) with `$workos->authorization()`
- Replace `VaultService` (Laravel `Http::`) with `$workos->vault()`
- Replace `RadarService` (Laravel `Http::`) with `$workos->radar()`
- Replace `PipesService` (Laravel `Http::`) with `$workos->pipes()`
- Replace `DomainService` (Laravel `Http::`) with `$workos->organizationDomains()`
- Replace `EventsListenCommand` manual HTTP with `$workos->events()`
- Replace `validateApiKey()` raw Guzzle with `$workos->apiKeys()`
- Replace `FeatureFlagService` SDK workarounds with `$workos->featureFlags()`
- Add typed facade accessors for new v5 services: `connect()`, `actions()`, `pkce()`, `multiFactorAuth()`, `adminPortal()`, `authorization()`, `passwordless()`
- Update `Widgets::getToken()` → `widgets()->createToken()`
- Update `WorkOSFake` and `InteractsWithWorkOS` trait for v5 patterns
- Update all existing tests for new class/method names
- Update Facade `@method` docblock for full v5 coverage
- Verify workbench app boots and auth flow works
