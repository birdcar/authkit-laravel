Inside the existing `Route::middleware(['auth:workos', 'workos.organization.current'])->group(...)` block, add a new route AFTER the existing todo and organization route groups:

```php
// Admin-only todo deletion via route (demonstrates workos.role middleware — D-09)
Route::delete('/todos/{todo}', function (\App\Models\Todo $todo) {
    $todo->delete();

    \WorkOS\AuthKit\Facades\WorkOS::audit('todo.deleted', [
        ['type' => 'todo', 'id' => (string) $todo->id, 'name' => $todo->title],
    ]);

    return response()->json(['message' => 'Todo deleted']);
})->middleware('workos.role:admin')->name('todos.destroy');
```

This creates a route-level RBAC demonstration per D-09: admins can delete any todo via this HTTP route (protected by CheckRole middleware), while regular members delete only their own via the Livewire TodoItem component (which has its own user-scoped authorization).

Route::get('/todos', function () {

**TodoTest.php — rewrite all 5 tests:**

For HTTP route tests (`$this->get('/todos')`), use `WorkOS::fake()->actingAs($user)` then call `$this->withSession(...)` and `$this->get(...)` separately (not chained from actingAs). The fake sets up the guard authentication.

For Livewire component tests, use `WorkOS::fake()->actingAs($user)` then `Livewire::test(ComponentClass)` (no need to pass guard to Livewire::actingAs anymore — the fake handles auth).
